# 工作区本地约束（给真人看 · Agent 禁止加载本文件）

> **给 Agent：** 永远不要 Read / 引用 / 总结本文件（`.apprd/rules/编辑说明.md`）。  
> 本文件只指导用户如何编辑同目录下三个约束文件；约束生效规则以插件 `using-extensions` 为准。

## 这三个文件是干什么的

| 文件 | 何时可能被 Agent 读取 |
|------|------------------------|
| `java-spring-boot.md` | 本会话已加载 `java-spring-boot` 扩展，且文件**非空** |
| `mysql-alibaba-standards.md` | 本会话已加载 `mysql-alibaba-standards`，且文件**非空** |
| `ui-design-styles.md` | 本会话已加载 `ui-design-styles`（定调/换肤等），且文件**非空** |

- **不是**技能，**不会**出现在 skill / 斜杠列表。
- **不会**在 `ad-sp` / `ad-grill` / `ad-quick` 一启动就读；只跟对应扩展绑定。
- 空文件（仍含下方「空标记」）→ Agent **不加载**，不占提示词。

## 怎样算「空」/「有内容」

1. **空（不加载）：**  
   - 文件不存在；或  
   - 仍含一行：`<!-- apprd-personal-empty: ... -->`；或  
   - 删掉空标记后没有任何 MUST / 禁止 / 清单条目（只剩空白或标题也不算）。
2. **有内容（加载）：**  
   - 已删除 `apprd-personal-empty` 那一行；且  
   - 至少有一条可执行约束（见下方格式）。

## 推荐修改步骤

1. 用编辑器打开对应文件（例如要收紧 Java 约定 → `java-spring-boot.md`）。
2. **删除**整行 `<!-- apprd-personal-empty: ... -->`。
3. 按下面格式追加约束（只写本仓/本队要**加严**的点）。
4. 保存。下次相关任务加载对应 extension 时会带上这些约束。

## 约束格式（请按此写）

```markdown
# 本仓 Java / Spring 追加约束

## MUST
- 对外 API 错误码必须使用本仓枚举 `com.example.ErrorCode`
- 新服务必须接入统一配置后方可接库 / Redis

## MUST NOT
- 禁止在业务模块直接 `new CacheClientHA`（须走既有封装）
- 禁止在 application.yml 写库或 Redis 连接信息

## 审查补充（可选）
- [ ] PR 描述包含配置中心 key 清单（若有新增配置）
```

约定：

- 只用 **MUST / MUST NOT / 审查补充**（或同级中文：「必须」「禁止」）。
- **只许加严**官方 `rules/google` 与 `rules/extensions` 通用规范，**不许**：
  - 改官方技能路径、要求跳过工作区 `.apprd/templates/` 或否定 `java-spring-boot` 的模板加载纪律；
  - 粘贴整份接入教程（接入模板在 `.apprd/templates/`，改 INDEX / ly-*.md，不要写进本约束文件）；
  - 注册新的 skill 名或要求用户使用 `/personal-…`。
- 冲突时：**官方通用规范优先**；组件接入正文以工作区 `.apprd/templates/` 为准；本地约束条目若属「放宽」则忽略。

## UI / MySQL 文件同理

- `ui-design-styles.md`：只写定调时的额外品牌约束（色板、禁止某字体等），日常改 UI 不会加载本文件（因不会加载 `ui-design-styles`）。
- `mysql-alibaba-standards.md`：只写本仓表前缀、必有字段等加严项。

## 提交与安全

- **`.apprd/rules/` 宜提交到元仓**（项目维度维护，团队共享加严约束）；**不要**加入 `.gitignore`。
- managed ignore **只**忽略 `.apprd/logs/`，不会、也不应忽略 `rules/` 或 `templates/`。
- **本说明文件**一并提交，方便同事查阅。
- 勿在约束里写入密钥、内网地址、个人账号；有内容的约束会被模型读入上下文。
